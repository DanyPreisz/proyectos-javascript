Lección 1 — Intro y primeras etiquetas

HTML básico · títulos, párrafos e imágenes

Hacé clic en el audio para mostrar el texto de esta lección.

0:005:00

Este curso masivo te va a preparar para ser desarrollador full stack. Lo dictan varios instructores y lo armó Scrimba. Acá está Per Harald Borgen, el CEO de Scrimba, presentando el curso.

Hola y bienvenida o bienvenido a este recorrido enorme para convertirte en desarrollador full stack. Estos módulos que estás por ver ya ayudaron a innumerables estudiantes en scrimba.com a entrar a la industria tecnológica como developers. Y no de esa forma teórica y aburrida. No. De una forma entretenida, en la que construís juegos, clonás Google e Instagram, armás apps de inversión con inteligencia artificial e incluso extensiones de Chrome. Y cuando digo “vos”, hablo en serio. Porque la única forma de aprender esto es escribir el código con tus propias manos.

A lo largo del curso, los profesores te van a tirar desafíos. De hecho, más de quinientas veces. El código inicial de esos desafíos está en GitHub o en scrimba.com, en la versión interactiva y ampliada de este curso.

Vamos a empezar con lo básico: HTML, CSS, JavaScript y lo que sigue. Después vamos a pasar a los frameworks y tecnologías que se usan en la industria: React, Node, Next, SQL, TypeScript, testing e incluso ingeniería con inteligencia artificial. Así que esto realmente es tu lugar de partida para convertirte en un desarrollador full stack profesional.

Me encantaría seguirte en este camino. Así que conectate conmigo en LinkedIn para poder alentarte desde la tribuna.

El filósofo francés René Descartes dijo tres palabras célebres: cogito, ergo sum, que en español se traduce como “pienso, luego existo”. Entonces, vamos a demostrarnos que existimos… programándolo en HTML.

La forma de hacerlo no es tan distinta de escribir en un editor de texto común. Ahí simplemente escribirías la oración. Y si quisieras que se viera más prominente, la seleccionarías y elegirías otro tipo de contenido: título uno, título dos, título tres. Si elegís título uno, el texto se vuelve mucho más destacado. Se convierte en un heading one.

En HTML hacemos lo mismo creando un archivo HTML. Acá se llama index.html, un nombre muy habitual para la página principal. En ese archivo escribimos etiquetas. Las etiquetas son como instrucciones para el navegador.

Para un título principal usamos la etiqueta h1. Se abre, va el texto, y se cierra. Eso le dice al navegador: “esto es el encabezado más importante de la página”.

Si querés un subtítulo, usás h2. Si querés un párrafo, usás la etiqueta p. HTML se trata de anidar elementos: un título, después un párrafo, después una imagen, y así se arma la estructura de la página.

Ahora vamos a hablar de imágenes, porque un artículo, por ejemplo sobre Marte, necesita una foto. Para eso usamos la etiqueta img. Lo particular de esta etiqueta es que no necesita cierre. Por eso se la llama etiqueta de autocierre.

Si recargás la página y no aparece nada, es porque todavía no le dijimos qué imagen mostrar. Eso se hace con el atributo src, que significa source, o fuente. Si el archivo se llama mars.jpg y está en la misma carpeta que index.html, alcanza con poner esa ruta.

Vas a notar que la imagen no se comporta igual que un párrafo. El párrafo ocupa todo el ancho; la imagen ocupa solo el ancho que necesita. HTML sirve para la estructura; CSS, para el estilo.

Resumen: HTML organiza el contenido con etiquetas. h1 y h2 son títulos. p es un párrafo. img muestra una imagen y usa src para indicar de dónde sale el archivo.

Lección 2 — Div, botón e input

Anidamiento, árbol del documento y campos de formulario

Hacé clic en el audio para mostrar el texto de esta lección.

0:004:37

Seguimos con HTML. El siguiente concepto clave es el anidamiento: poner elementos HTML dentro de otros elementos HTML.

Imaginá que querés agrupar todo un artículo: el título, la imagen, el subtítulo y los párrafos. Arriba de esas etiquetas abrís otra, y abajo las cerrás. La etiqueta que se usa para eso se llama div. Viene de divider, divisor, aunque un nombre más claro sería contenedor.

Para que el código se lea bien, se indentan las etiquetas de adentro. Así el h1, la imagen, el h3, el párrafo y la otra imagen quedan como hijos de ese div. En pantalla no cambia nada: el div es invisible. Pero ahora podés apuntar a todo el artículo de una sola vez, y eso sirve después para darle estilo con CSS o manipularlo con JavaScript.

En una página real vas a ver un montón de divs. Si lo dibujás, parece un árbol genealógico: un tronco, ramas, y más ramas saliendo de esas ramas. Por eso a esta estructura se la llama árbol del documento HTML.

En ese árbol también aparece la etiqueta a, el ancla. Todavía no la usamos en profundidad, pero es la que crea enlaces.

En Chrome, si hacés clic derecho sobre un texto de una página y elegís Inspeccionar, se abren las DevTools. En la pestaña Elements ves el HTML real. Ahí podés leer las etiquetas, ver cómo están anidadas y hasta cambiar el texto para entender la estructura.

La etiqueta button se abre, adentro va el texto que el usuario ve, y se cierra. En el navegador aparece un botón. Por ahora no hace nada útil: para enviar datos o ejecutar lógica hace falta JavaScript.

Desafío típico: una pantalla de bienvenida para registrarse. Arriba un h1 que saluda. Después un párrafo con un mensaje corto. Abajo un botón que diga Sign up. Lo importante es poner bien las tres etiquetas.

Ese formulario sigue incompleto, porque el usuario no puede escribir su nombre ni su contraseña. Ahí entra la etiqueta input.

Input, igual que img, es de autocierre. Lo obligatorio es decir de qué tipo es, con el atributo type. El más común es text: una caja de texto.

El atributo placeholder deja una pista, por ejemplo Enter username. Después se agrega un segundo input para la contraseña. En el mundo real las contraseñas no se muestran: se cambia el type a password y los caracteres quedan enmascarados.

type="date" abre un selector de fecha. type="time", uno de hora. type="color", uno de color.

Resumen: Div agrupa elementos y no se ve, pero organiza el árbol. Button crea un botón. Input crea campos. HTML sigue siendo estructura. La interacción de verdad llega después, con JavaScript.

Lección 3 — Archivos, documento y listas

input file, estructura HTML y listas ordenadas o desordenadas

Hacé clic en el audio para mostrar el texto de esta lección.

0:004:09

Seguimos armando formularios y después pasamos a la estructura real de una página y a las listas.

El input es una herramienta muy versátil. Además de texto, contraseña, fecha, hora y color, también sirve para subir archivos. Si querés que alguien cargue una foto de perfil, el type que buscás es file. En el navegador se ve como un botón que dice Elegir archivo. Al hacer clic, se abre el explorador de la computadora y la persona puede elegir una imagen.

Eso no se adivina de memoria. Una parte enorme de programar es saber buscar. Una búsqueda útil sería: HTML input upload image files. En la documentación vas a encontrar exactamente type="file". Lo agregás arriba del botón de registro y el formulario ya deja cargar una foto.

Con lo que sabés hasta ahora también podés armar una página que se parezca a un buscador. No hace falta magia: un título o un logo en el centro, debajo un input de tipo text que simula el campo de búsqueda, y dos botones. Uno puede decir Buscar y el otro Me siento con suerte. Es un ejercicio de estructura, no de copiar una marca.

Hasta acá veníamos tirando etiquetas sueltas. Un documento HTML de verdad tiene una estructura fija.

Arriba va el doctype: le dice al navegador que estamos usando HTML 5. Después se abre html, que envuelve todo. Adentro hay dos grandes bloques. El head guarda lo que no se ve tanto: el título de la pestaña, el idioma, los estilos. El body guarda lo visible: títulos, párrafos, imágenes, botones, listas.

Si envolvés una página que ya funcionaba con body, head, html y doctype, en pantalla casi no cambia nada. El cambio está debajo: el archivo queda bien formado y el navegador entiende el documento como corresponde.

Ahora, las listas. Sirven cuando querés enumerar cosas: países, pasos, ingredientes, lo que sea.

Hay dos etiquetas que trabajan juntas. Una envuelve la lista entera. La otra marca cada ítem.

Si el orden importa, usás ol: ordered list, lista ordenada. Adentro, cada elemento va con li. El navegador pone 1, 2, 3 solo. Ejemplo: Noruega, Alemania, China.

Si el orden no importa, usás ul: unordered list. Los ítems también van con li, pero el navegador dibuja viñetas. Café, té y código no necesitan ranking.

Podés anidar listas, igual que anidás divs. Un li puede contener otra ul o otra ol. El árbol del documento sigue siendo la misma idea: padres e hijos.

Resumen: type="file" abre el selector de archivos. Una página de buscador se arma con un campo de texto y botones. El documento correcto lleva doctype, html, head y body. ol numera. ul pone viñetas. li es cada elemento de la lista.

Lección 4 — Enlaces y primer CSS

Proyecto personal, etiqueta a y hoja de estilos

Hacé clic en el audio para mostrar el texto de esta lección.

0:003:26

Cerramos esta primera tanda de HTML con un proyecto personal, los enlaces y el primer contacto con CSS.

Las listas no son solo para documentos aburridos. En muchos sitios la barra de navegación es una lista desordenada: un ul que envuelve varios li. Cada categoría del menú es un ítem. Cuando llegue CSS vas a poder estilar esa lista y convertirla en un menú horizontal.

El proyecto de esta sección es una web sobre vos. Empieza simple: una foto, un h1 con tu nombre, un h2 de datos, una lista con tres datos personales, un párrafo y un lugar para unirse a un boletín. Después se personaliza: género de películas favorito, fruta favorita, modo claro u oscuro, bordes filosos o redondeados. Cada elección cambia la cara de la página.

El elemento nuevo más importante acá es el enlace. La etiqueta se llama a, de anchor, ancla. El texto que se ve es el que va entre la apertura y el cierre. El destino se escribe en el atributo href. Si querés que “LinkedIn” lleve a tu perfil, envolvés esa palabra con a y en href ponés la URL.

Un extra útil es target="_blank": el enlace se abre en una pestaña nueva y no te saca de tu sitio.

También aparece otra etiqueta link, distinta de a. Esta no es para que el usuario haga clic. Vive en el head y conecta el HTML con un archivo de estilos. rel="stylesheet" le dice al navegador que el recurso es una hoja de estilo. Href apunta a styles.css. Si sacás esa línea, la página vuelve al aspecto crudo del navegador. Si la dejás, el CSS entra y pinta el documento.

CSS funciona así: elegís un elemento, abrís llaves y adentro escribís propiedades. El elemento que elegís se llama selector. Si el selector es body, las reglas se aplican a todo lo visible de la página.

Una regla típica: body, llave de apertura, color, dos puntos, red, punto y coma, llave de cierre. Color acá significa color de texto. La propiedad va antes de los dos puntos. El valor va después. Cada declaración termina en punto y coma.

Si cambiás blue por red, el texto del body se pone rojo. HTML sigue siendo la estructura. CSS es el estilo: color, espacio, tipografía, bordes.

Resumen: ul puede ser un menú. a y href crean enlaces. target blank abre otra pestaña. link rel stylesheet conecta un archivo CSS. Un selector, llaves, propiedad y valor: esa es la sintaxis básica de CSS.

Lección 5 — Propiedades CSS

Color, tipografía, margen y primeras clases

Hacé clic en el audio para mostrar el texto de esta lección.

0:002:48

Escribimos las primeras líneas de CSS de verdad: propiedades, valores y el modelo de caja.

Una regla CSS termina sí o sí con punto y coma. Si te lo olvidás, se rompe el ejemplo. El selector elige el elemento. Entre llaves van las declaraciones.

Propiedades que vas a usar ya mismo.

background-color pinta el fondo. color pinta el texto. No son lo mismo. Podés usar nombres que CSS ya conoce, como white o saddle brown, o más adelante códigos hexadecimales.

font-size controla el tamaño de la letra. En esta etapa se mide en px, píxeles. 200 px es enorme. 25 px suele verse razonable para un texto de widget.

font-weight es el grosor: normal o bold, o un número como 400 y 700.

text-align alinea el texto: left, center o right.

margin-top agrega espacio arriba del elemento. También se mide en px. Si ponés 100 px, el contenido baja.

Los comentarios en CSS van entre barra asterisco y asterisco barra. El navegador los ignora. Sirven para dejar pistas.

Un consejo de estructura: no le pongas el margin top a la imagen si esa imagen algún día puede cambiar. Mejor envolvés el bloque en un div y le das el margen al contenedor. El div no se ve, pero sostiene el diseño cuando el contenido de adentro cambia.

Eso conecta con las clases. Si seleccionás solo img o solo div, cuando agregues más imágenes o más divs el estilo se aplica a todos y aparecen bugs. La clase te deja marcar un elemento puntual. En HTML escribís class="main". En CSS lo seleccionás con un punto: .main. Así estilás esa caja y no todas las cajas.

Resumen: propiedad, dos puntos, valor, punto y coma. Background color es el fondo. Color es el texto. Font size y font weight cambian la tipografía. Margin top separa por fuera. Las clases, con un punto en CSS, evitan que un selector genérico pinte de más.
